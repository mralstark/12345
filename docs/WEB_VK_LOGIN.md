# Веб-кабинет и VK ID

Этот документ описывает необязательный вход в обычном браузере через VK ID
(OAuth code + PKCE). База, разделы, роли, статьи, Академия и отчёты общие
с Telegram Mini App и [VK Mini App](VK_MINI_APP.md).

Прямой вход через `https://vk.ru/app54848740` уже реализован отдельно:
он проверяет подписанные параметры запуска VK и не требует `VK_ID_CLIENT_ID`
или cookies третьей стороны. Его настройка и регистрация описаны в
[VK_MINI_APP.md](VK_MINI_APP.md). Переменные и идентификаторы двух интеграций
не взаимозаменяемы. Пока `VK_ID_CLIENT_ID` не задан, обычный браузер предлагает
Telegram-вход и ссылку Mini App; OAuth-кнопка VK ID не показывается.

## Включение

1. Создать веб-интеграцию в кабинете [VK ID](https://id.vk.ru/).
   Официальный [SDK и документация](https://github.com/VKCOM/vkid-web-sdk)
   описывают получение APP_ID и настройку redirect URI.
2. Указать сайт `https://lk.31-129-98-217.sslip.io` и точный redirect URI:
   `https://lk.31-129-98-217.sslip.io/api/auth/vk/callback`.
3. Включить передачу телефона с согласия пользователя: новый участник не
   может подменить номер самостоятельно в анкете. Если VK не передаёт
   полный номер, форма предлагает повторить вход с разрешением телефона.
4. В серверном `.env` задать публичный идентификатор интеграции:

   ```dotenv
   VK_ID_CLIENT_ID=ВАШ_ЧИСЛОВОЙ_APP_ID
   ```

   ID сообщества или другого неподключённого приложения для этого не подходит.
   Токены пользователей и сервисные ключи VK в `.env` не нужны и в браузер
   не передаются. Без APP_ID VK-кнопки скрыты; Telegram-вход сохраняется.
5. Установить проверенную версию кода с резервной копией и миграцией
   `python -m scripts.migrate_web_identity`, затем перезапустить API и бота.
   Все штатные deploy-сценарии выполняют миграцию после базовой схемы,
   до миграций, читающих текущую ORM.
6. Проверить реальное подключение: существующий участник связывает VK,
   выходит из браузера, входит через VK ID и видит прежний кабинет.
   Затем проверить новую анкету, одобрение и отказ в доступе до одобрения.
   Проверка с имитацией провайдера не заменяет эти шаги после получения APP_ID.

Публичная веб-ссылка: `https://lk.31-129-98-217.sslip.io/?web=1`.
При смене домена нужно обновить WEBAPP_URL и адрес возврата в VK ID.

## Существующий участник

Открыть свой кабинет в Telegram заново, нажать меню кабинетов → «Способы
входа» → «Подключить VK ID». Подтвердить вход в нужный VK-аккаунт.
После подключения обычный браузер открывает тот же User/Member, роли и
историю. Для подключения или отключения требуется свежий подписанный
вход Telegram, не старше пяти минут. В режиме «Войти как» изменения запрещены.
Один VK ID связывается с одним кабинетом, один кабинет — с одним VK ID.

Номер и ФИО не используются для автоматического объединения. Если VK ещё
не связан, а телефон уже есть в кабинете, форма предлагает войти прежним
способом и подключить VK. Если Telegram недоступен и привязка заранее не
сделана, требуется обращение к руководителю для проверки личности.

## Новый участник без Telegram

Войти с VK ID, разрешить передачу номера, заполнить прежнюю анкету и
отправить её руководителю. До одобрения доступен только статус своей заявки.
После одобрения создаётся обычный участник с личным кабинетом, без
управленческих прав. Существующая заявка показывается повторно, не создавая
новую при каждом заходе. Статус можно обновить кнопкой в форме.

Такой аккаунт может работать только через веб и VK ID. Telegram ID не
подставляется фиктивным числом и не назначается по номеру телефона. Подключение
Telegram к созданному через VK аккаунту требует отдельного подтверждения;
оно не выполняется автоматически этой интеграцией. Сообщения бота не
отправляются пользователям без привязанного Telegram, данные остаются доступны
в веб-кабинете. Уведомления о новых заявках руководителям отправляются фоном.

## Проверки и границы

- Одноразовый state связан с HttpOnly-cookie браузера, ограничен десятью
  минутами и атомарно потребляется до обмена кода. PKCE verifier остаётся на
  сервере. Проверяются state ответа и совпадение ID токена с user_info.
- Callback и адрес провайдера фиксированы. Клиент может передать только
  положительный ID статьи для возврата после входа; произвольный redirect
  не принимается. Статья всё равно проверяет права доступа.
- Токены VK не сохраняются в БД/браузере/URL приложения. Ответы провайдера
  читаются с ограничением размера и времени, внешние HTTP-переадресации
  запрещены. Отмена и отказ входа не показывают ответ провайдера целиком.
- После входа создаётся новый секрет браузерной сессии. Cookie Secure в
  production, HttpOnly, SameSite=Strict; мутации проверяют Origin. Отдельная
  cookie попытки OAuth имеет SameSite=Lax для возврата с сайта провайдера.
- Пользователи без Telegram ID разрешаются по User.id. Права и деактивация
  проверяются в БД при запросах. Существующие способы входа и роли не меняются.
- Обычная веб-страница загружает только локальный bootstrap. Telegram SDK
  запрашивается только в контексте Mini App. При ошибке загрузки доступны
  повтор и веб-вход; обычный браузер не ждёт `telegram.org`.
- Миграция сохраняет Telegram-заявки и сессии, поддерживает PostgreSQL и
  SQLite. Откат к старому API запрещается, если уже появились связанные
  VK-пользователи без Telegram ID. Новые столбцы при откате не удаляются.

Проверки реального VK ID требуют созданной интеграции и участия владельца
аккаунта. Пока APP_ID не задан, нельзя считать реальный вход проверенным.
