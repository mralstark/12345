# Надёжность кабинета — 16 октября 2026

Изменения совместимы с прежними мероприятиями и клиентами Mini App.
Новый параметр `total_attendees` необязателен: `null` означает, что общее
число посетителей неизвестно. Ноль — явно указанное значение. Чек-лист
членов отделения хранится независимо; отчёты XLSX/PDF показывают обе графы.
При создании повторов посещаемость предыдущего мероприятия не копируется.

## Вход в обычном браузере

Сайт предлагает подтвердить вход в личном чате с ботом. Пользователь сверяет
шестизначный код сайта с кодом сообщения и нажимает кнопку подтверждения.
Сам переход по ссылке вход не подтверждает. Регистрация и доступ к кабинетам
сохраняют действующие правила; вход не создаёт нового пользователя и не выдаёт
ему дополнительных ролей.

Подтверждение действительно пять минут и используется один раз. Отдельный
браузерный секрет хранится в HttpOnly cookie, в production — Secure,
SameSite=Strict, без Domain, с префиксом `__Host-`. В БД хранятся только хэши
секретов; сессия живёт 12 часов. Есть кнопка выхода. Изменения через cookie
требуют точный Origin сайта. При каждом запросе заново разрешаются действующие
права пользователя. Блокировка/удаление аккаунта закрывает доступ сессиям.

## Скачивание файлов

После формирования отчёта остаются кнопки скачивания и возврата в кабинет.
Telegram 8.0+ использует `WebApp.downloadFile`; старые клиенты — внешний
браузер, обычный браузер — ссылку с `Content-Disposition: attachment`.
Финансовый CSV и документы используют тот же механизм.

Одновременные/повторные нажатия не запускают повторную генерацию. На сервере
не более двух одновременных подготовок, действуют ограничения частоты запросов.
Ссылка — подписанная возможность скачать конкретный файл, а не initData или
браузерный секрет; срок действия 10 минут. Повторно проверяются активность
аккаунта, регион и область доступа, для документов — существование документа.
Смена прав не сохраняет прежний доступ к отчёту. Разрешены GET и HEAD.

Экспорты хранятся под `STORAGE_DIR/report_downloads`, до 20 МиБ на файл и
256 МиБ суммарно. Истёкшие файлы удаляются при следующей подготовке. Для
документов сохраняется только пустой маркер ссылки; файл читается из исходного
защищённого хранилища. Квота свободного диска также проверяется.

Nginx ведёт журнал без query string; дублирующий access log uvicorn отключён,
чтобы подписанные ссылки не попадали в journald. Журнал ошибок сохранён.
Режим «Войти как» разрешает подготовку файлов как операцию чтения, но запрещает
изменение данных.

## Медиа и соединения

При ошибке картинки клиент получает свежую подписанную ссылку через
авторизованный API. Обработчик зарегистрирован из JS и работает при действующем
CSP. Повторы ограничены, запросы выстроены в очередь; при возобновлении
приложения обновляются истекающие ссылки видимых изображений. Срок подписи
и проверка доступа сохранены.

SQLAlchemy проверяет соединения перед использованием и обновляет старые
соединения. Перезапуск бота больше не удаляет необработанные Telegram updates.
Сетевые сбои самого Telegram остаются внешней зависимостью; polling использует
повторы aiogram.

## Установка

Все сценарии установки/обновления запускают повторяемую аддитивную миграцию
`python -m scripts.migrate_service_reliability`: поле посещаемости и таблицу
браузерных сессий. Старые события и данные сохраняются. Новых переменных `.env`
нет: используются действующие `WEBAPP_URL`, `BOT_TOKEN`, `MEDIA_SIGNING_KEY`,
`STORAGE_DIR`. Требуется перезапуск API и бота, синхронизация systemd unit.

`multidict` обновлён до 6.9.1 в обоих lockfiles, с хэшами файлов релиза PyPI.
В требованиях закреплена минимальная исправленная версия. Это исправляет
GHSA-54p9-h82j-f925. Проверяется освобождение ссылок в двух затронутых операциях.

Входной `requirements-dev.txt` ссылается на `requirements.txt`, чтобы Dependabot
мог собрать граф зависимостей из поддерживаемых pip-манифестов. CI устанавливает
оба lockfile одной командой: несовпадение production/dev версий приводит к
ошибке установки, а не к проверке другого окружения. `.python-version` закрепляет
Python 3.12 для инструментов анализа, как на сервере и в CI.
