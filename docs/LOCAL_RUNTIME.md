# Локальный запуск на Windows

Для повседневного запуска используется одна задача планировщика
`Bratstvo-Local-Recovery`. Она запускается по требованию, без автоматической
рассылки и без дополнительных платных сервисов. Закрытие окна PowerShell не
должно останавливать приложение. При выключенном компьютере приложение недоступно.

```powershell
Start-ScheduledTask -TaskName 'Bratstvo-Local-Recovery'
```

Текущий путь настройки хранится в аргументах задачи; секреты в JSON контроллера
не помещаются. В нём заданы code_dir, runtime_dir, state_dir, postgres_bin,
postgres_data, bot_script и ssh_known_hosts. Сервис читает существующий
зашифрованный runtime .env, API и бот получают его только в окружении процесса.
Ключ данных остаётся отдельно. Для прямого запуска контроллера:

```text
python -m scripts.local_runtime --config C:\private\local-runtime-config.json
```

## Что проверяется

- `/healthz` — процесс API отвечает. Этот ответ не доказывает работу базы.
- `/readyz` — соединение с БД, актуальная опись шифрования и подлинность canary.
  Проверки ограничены по времени и кратко кешируются. Ошибка даёт общий 503
  без строки подключения, персональных данных и ключей.
- Состояние PostgreSQL, собственного процесса API и heartbeat/polling бота.
- Внешний HTTPS-маршрут до `/readyz`, с обычной проверкой сертификата.

Публичные HTML/JS/CSS/SVG сжимаются gzip при поддержке клиентом. Ответы API,
личные файлы и отчёты этим сжатием не затрагиваются. Загрузчик интерфейса
допускает до 90 секунд на файл: бесплатный туннель может ограничивать скорость.
Это конечное ожидание, после него остаются кнопки повторной попытки и веб-входа.

API, бот и туннель восстанавливаются раздельно. Краткий сбой внешнего маршрута
не перезапускает локальный API и не прерывает polling бота. Новое имя туннеля
требует обновить разрешённый host и кнопку бота, поэтому в этом случае процессы
перезапускаются согласованно. Работает только один контроллер и один poller;
не запускать второй `bot.py` параллельно с задачей.

В state_dir находятся services.json, bot-health.json и recovery-events.json
с кодами последних событий. Поток SSH не сохраняется: в нём могут быть пути
запросов и временные ссылки. Регистрация туннеля извлекается только из события
соответствующего типа; неизвестные строки не меняют адрес приложения.
Предыдущие логи API/бота ограниченно сохраняются при перезапуске.
Полные access-логи Uvicorn отключены, чтобы не сохранять временные ссылки
и параметры запросов; журнал действий с шаблонами маршрутов остаётся включён.

## Бесплатный туннель и старые кнопки

Анонимный localhost.run выдаёт временные домены. По
[официальным условиям](https://localhost.run/docs/forever-free) бесплатное имя
периодически меняется; контроллер не может сделать его постоянным.
SSH-ключ без регистрации в сервисе не был принят при проверке. Для более
долгой жизни имени сервис предлагает аккаунт и привязку публичного ключа.
Это не настроено автоматически и не заменяет постоянный адрес для эксплуатации.

После смены адреса нужно отправить `/start` и открыть новую кнопку либо
обновлённое меню бота. Кнопка из старого сообщения может содержать истёкший
адрес. Настройка основной кнопки в профиле бота через BotFather — отдельная
настройка Telegram; обновление chat menu её не изменяет.

## Остановка и обновление

Создать пустой файл stop-requested в state_dir и дождаться
`services.json: phase=stopped`. Удалить только этот файл перед новым запуском.
Не останавливать всё Python/SSH по имени: на компьютере есть другие процессы.

Перед обновлением остановить единственный API/бот, сохранить проверенную
зашифрованную копию, обновить обе папки кода без перезаписи .env/.venv/данных,
затем запустить задачу и проверить readyz, polling и актуальность меню.
Различия только CRLF/LF не являются разными версиями исходного кода.

Плановые рассылки в текущем локальном режиме остаются приостановленными;
VK-вход отключён по решению владельца. Запуск контроллера не размораживает их.
