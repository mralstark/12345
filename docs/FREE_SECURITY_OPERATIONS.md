# Бесплатная эксплуатационная защита

Эти меры используют существующий VPS, GitHub и компьютер владельца.
Они не защищают канал Beget от объёмного DDoS и не обеспечивают высокую
доступность при полном отказе единственного VPS. Платные сервисы не включаются.

## Контроль состояния

`bratstvo-monitor.timer` запускает проверку раз в пять минут. Проверяются
службы, HTTPS, срок сертификата, соединение с PostgreSQL и Telegram API,
свободное место, свежесть резервной копии и результат её создания,
права `.env` и необходимость перезагрузки после обновлений безопасности.
Автоматическая перезагрузка и исправления данных не выполняются.

Результат хранится в `/var/lib/bratstvo-monitor/status.json`, доступном root.
При изменении состояния и при ошибках в journald записываются только коды
проверок. По умолчанию Telegram-рассылка не включена: получатель должен быть
явно согласован с владельцем. Это локальный контроль: при полном отказе
сервера его собственный монитор тоже перестаёт работать.

Проверка вручную: `systemctl start bratstvo-monitor.service`.
Диагностика: `journalctl -u bratstvo-monitor.service`.
Для альтернативного каталога бэкапов задайте `--backup-dir` в override юнита.

## Журналы

Изменяющие API-запросы записывают в journald идентификатор действительного
пользователя, идентификатор просматриваемого аккаунта, метод, шаблон маршрута
и HTTP-результат. Тела запросов, имена, телефоны, cookies и подписанные
параметры входа не записываются этим аудитом. Повторный ответ из кэша
идемпотентности не считается новым выполненным действием.
Это журнал API, а не полный аудит всех действий бота или неизменяемый реестр.

У настроенных обработчиков журналирования API и бота секреты конфигурации
маскируются после форматирования, включая traceback. SQLAlchemy скрывает
значения SQL-параметров в исключениях. Access log nginx не содержит query,
Referer и User-Agent. Низкоуровневые журналы nginx нужно по-прежнему хранить
приватно: стандартные сообщения ошибок могут содержать URI запроса.

## Аутентификация резервной копии

Новая копия состоит из двух файлов: `bratstvo-*.tar.gz.enc` и соседнего
`.enc.hmac`. Шифрование OpenSSL остаётся совместимым с прежним форматом.
HMAC-SHA256 аутентифицирует имя и зашифрованное содержимое с отдельным ключом,
полученным из существующего приватного ключа с разделением назначения.
Проверка выполняется до расшифровки, чтобы не принимать повреждённые или
подменённые архивы. Копии читаются блоками; размер архива не определяет расход RAM.

Проверить: `python -m scripts.backup_integrity verify АРХИВ --key-file ФАЙЛ_КЛЮЧА`.
Только после успешной проверки расшифруйте копию прежней командой OpenSSL
AES-256-CBC с PBKDF2. Внешний tar содержит `database.dump`, `storage.tar.gz`
и `application.env` — конфигурацию сервера с секретами внутри зашифрованной копии.
Ключ расшифровки никогда не включается в этот архив.
Восстановление проверяют в отдельной БД и отдельной папке, затем сверяют данные;
никогда не запускайте тест восстановления поверх production.

Старые копии без `.hmac` остаются расшифровываемыми, но не считаются
аутентифицированными новым средством. Сохраняйте их как прежние доверенные
снимки, не создавайте подпись для архива неизвестного происхождения.

## Копия вне VPS без облачной подписки

`deploy/pull_backup.py` скачивает только зашифрованный архив и HMAC через SSH
с проверкой известного ключа сервера. После проверки локальным ключом
архив публикуется в приватной папке; временная загрузка не считается копией.
На компьютере владельца папку защищают ACL, а ключ восстановления хранят
отдельно от архивов. При полностью выключенном компьютере загрузка не работает.

Пример: `python deploy/pull_backup.py --server root@31.129.98.217`.
Параметры `--destination`, `--key-file` и `--identity` задают локальные пути.
По умолчанию используются `.bratstvo-backups` и приватные файлы в `.ssh`
профиля владельца. Открытый `.env` этим сценарием не скачивается: конфигурация
находится только внутри аутентифицированного зашифрованного архива. Секреты
Telegram/VK владелец должен также сохранить в собственном менеджере паролей.

Планировщик Windows можно запускать ежедневно с правами текущего пользователя,
без хранения пароля, только в его интерактивном сеансе. Включите выполнение
пропущенного запуска при следующем входе. Локальное расписание не является
удалённым круглосуточным мониторингом.

## Что остаётся владельцу

Включите двухфакторную аутентификацию и сохраните резервные коды для Beget,
GitHub, аккаунта Telegram/VK и регистратора, если появится собственный домен.
Секреты и коды не отправляйте в чат. Такие подтверждения и добавление
аутентификатора выполняет сам владелец на своём устройстве.
