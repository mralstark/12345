# Личный кабинет Братства Академистов — волна 1

Гибрид Telegram-бота и Mini App: бот отвечает за вход, уведомления, задачи
и быструю запись расходов; Mini App — за всё, что требует таблиц и форм (состав,
финансы, мероприятия, документы, аналитика, отчёты). Общая БД и общий код.

Реализовано по ТЗ «Волна 1»: вертикаль superuser → федеральный координатор →
координаторы регионов → руководители региональных отделений → руководители
вузовских ячеек.

## Структура

```
bot.py                  точка входа Telegram-бота (aiogram 3.x)
api/main.py             точка входа бэкенда Mini App (FastAPI)
api/auth.py             проверка подписи Telegram initData — вход в кабинет
api/routers/            эндпоинты по модулям ТЗ
webapp/                 Mini App: index.html + app.js + styles.css, без сборки
database/models.py      схема данных (ТЗ §15)
services/               общая для бота и API логика: финансы, задачи,
                        новости, повторы мероприятий, отчёты, нотификатор
utils/access.py         правила видимости регионов по ролям (ТЗ §3)
scripts/admin.py        CLI: регионы, люди, ссылки-приглашения
scripts/seed_demo.py    демо-данные для локальной проверки
tests/                  pytest: доступы, финансы, повторы, initData, API
```

## Как начать работу над проектом

Раздел для того, кто пришёл в проект. Ниже, в «Быстром старте», — как поднять
систему целиком; здесь только то, что нужно, чтобы писать код.

**Понадобится** Python 3.12 (та же версия, что на сервере) и git.

**Заведите себе отдельного бота.** Боевой токен не берите — с ним можно
писать от имени бота всем, кто в нём есть, и это не откатить. Напишите
[@BotFather](https://t.me/BotFather), команда `/newbot`, он выдаст токен вида
`123456:AAE...`. Это ваш личный бот для отладки, к Братству он отношения не
имеет.

**Поставьте проект:**

```bash
git clone https://github.com/mralstark/12345.git
cd 12345
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-dev.lock
```

На Windows вместо `.venv/bin/python` везде `.venv/Scripts/python.exe`.

**Настройте окружение:**

```bash
cp .env.example .env
```

В `.env` заполните `BOT_TOKEN` своим токеном от BotFather. Остальное можно
оставить как есть: база по умолчанию — файл SQLite рядом с проектом, Postgres
локально не нужен.

**Проверьте, что всё встало:**

```bash
.venv/bin/python -m pytest -q
```

Если тесты проходят — окружение рабочее, никаких
секретов им не нужно, они работают на подставных значениях.

### Как устроена работа

Боевой сервер разворачивается из `main`, поэтому сломанный `main` — это
сломанное приложение у людей. Отсюда весь порядок:

1. **Ветка на задачу.** От `main`, с говорящим именем: `git switch -c
   fix-task-deadlines`. Не копите в одной ветке месяц — однажды так вышло, что
   ветка «фотографии новостей и нижняя панель» набрала 78 коммитов про совсем
   другое.
2. **Пишите код и тесты.** Меняете правило — поправьте проверку, которая его
   стерегла. Тест, подогнанный под новое поведение, бесполезен; тест должен
   говорить, почему правило именно такое.
3. **Прогоните тесты у себя** перед отправкой.
4. **Откройте pull request** в `main`. GitHub сам прогонит тесты на чистой
   машине (`.github/workflows/tests.yml`) и покажет результат в PR.
5. **Слияние и выкладка — у владельца проекта.** Выкладка идёт по SSH под
   root на боевой сервер, там персональные данные всего состава, поэтому
   ключи не раздаются вместе с доступом к репозиторию.

## Быстрый старт

Как поднять систему целиком — завести регионы, назначить руководителей,
запустить бота и бэкенд. Если вы пришли писать код, вам выше, в «Как начать
работу над проектом».

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.lock
```

На Windows вместо `.venv/bin/python` везде `.venv/Scripts/python.exe`.

Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`. Локально по умолчанию
используется SQLite-файл `bratstvo.db` — Postgres не нужен.

Заведите регион:

```bash
.venv/bin/python -m scripts.admin region-add "Москва"
```

Команда напечатает ссылку саморегистрации вида `https://t.me/имя_бота?start=APPLY_XXXX` —
её отдают будущему руководителю. Управленческая роль назначается только уже
саморегистрированному человеку (найдите его id через `members-search`):

```bash
.venv/bin/python -m scripts.admin members-search "Иванов" --region "Москва"
```

```bash
.venv/bin/python -m scripts.admin user-add --member-id 1 --role leader --region "Москва"
```

Аналогично назначаются `--role coordinator --regions "Москва,Тула"` и `--role federal`.

Запуск бота и бэкенда — два отдельных процесса:

```bash
.venv/bin/python bot.py
```

```bash
.venv/bin/python -m uvicorn api.main:app --host 0.0.0.0 --port 8000
```

## Mini App

Telegram открывает WebApp только по HTTPS. Пропишите публичный адрес в `WEBAPP_URL`
— тогда в меню бота появится кнопка «🏛 Открыть кабинет». Для локальной отладки
поднимите туннель (`cloudflared tunnel --url http://localhost:8000` или ngrok) и
положите его адрес в `WEBAPP_URL`.

Посмотреть интерфейс в обычном браузере, без Telegram:

```bash
.venv/bin/python -m scripts.seed_demo
```

затем поставьте в `.env` `DEV_TELEGRAM_ID=900001` (руководитель), `900003`
(координатор) или `900004` (федеральный) и откройте `http://localhost:8000`.
**На сервере эта переменная обязана быть пустой** — она отключает проверку подписи.

Быстрая проверка после запуска API:

```bash
curl http://127.0.0.1:8000/healthz
```

Ожидаемый ответ: `{"status":"ok"}`. Интерактивная документация API в режиме
development доступна по адресу `http://127.0.0.1:8000/docs`.

## Как устроен доступ

| Роль | Видит | Правит |
|---|---|---|
| superuser | всё | всё (техническая роль для отладки) |
| федеральный координатор | все регионы | задачи, новости от имени Братства |
| координатор регионов | назначенные ему регионы | задачи, новости от имени Братства |
| руководитель отделения | свой регион | состав, финансы, мероприятия, документы, новости от имени отделения |
| руководитель вузовской ячейки | свою ячейку внутри региона | состав, финансы, мероприятия и задачи своей ячейки |

Координаторы и федеральный работают с данными региона **в режиме просмотра** —
так в ТЗ §6, §7, §9. Всё это собрано в `utils/access.py`, и на это есть тесты.

Первому человеку в пустой системе приглашение выдать некому: впишите свой
`telegram_id` (команда `/whoami` в боте) в `SUPERUSER_TELEGRAM_IDS`.

## Уведомления

Фоновый цикл в процессе бота (`services/notifier.py`) раз в 15 минут проверяет
дни рождения, приближающиеся дедлайны и просрочки, а заодно досоздаёт
повторяющиеся мероприятия на 90 дней вперёд. Все проверки идемпотентны по дню —
перезапуск бота не приводит к повторной отправке.

## Тесты

```bash
.venv/bin/python -m pytest -q
```

Тесты проверяют правила доступа и роли, кто и откуда пишет в ленту, задачи и их
статусы, задания и цена ступеней, регионы и вузовские ячейки, финансы,
повторы мероприятий, модерация текстов, обработка фотографий, проверка подписи
initData (включая подделку и протухшие данные), исключение человека из состава
и сквозные проверки API по всем модулям, включая отказы в доступе.

Именно `python -m pytest`, а не просто `pytest`: первый кладёт корень проекта
в пути импорта, второй — нет, и тесты падают на «No module named 'api'».

## Деплой

1. PostgreSQL: `DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/bratstvo`.
   При обновлении запускайте `python -m scripts.migrate_security_constraints` и
   `python -m scripts.migrate_university_active`;
   штатные deploy-скрипты делают это автоматически до перезапуска сервисов.
2. Два systemd-юнита: `bot.py` и `uvicorn api.main:app`. Один и тот же `.env`.
3. Nginx с TLS перед uvicorn — Telegram открывает Mini App только по HTTPS.
4. `STORAGE_DIR` держите вне каталога с кодом. Настройте `MAX_STORAGE_MB` и
   `MIN_FREE_STORAGE_MB`; БД и файлы копируйте зашифрованными на отдельный диск.
5. `.env` не копируйте с машины разработчика: `BOT_PROXY_URL` и `DEV_TELEGRAM_ID`
   там локальные и на сервере всё сломают.
6. Для PDF-отчётов на сервере нужен шрифт с кириллицей
   (`apt install fonts-dejavu-core`) либо явный `REPORT_FONT_PATH`.

В production обязательны `APP_ENV=production`, точный `ALLOWED_HOSTS`, HTTPS в
`WEBAPP_URL` и отдельный случайный `MEDIA_SIGNING_KEY`. Запуск останавливается,
если включён отладочный `DEV_TELEGRAM_ID` или осталась небезопасная настройка
выдачи роли по ФИО. Рабочий пример находится в `.env.example`.
